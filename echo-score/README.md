# 声骸评分 OK Script

版本：**0.4.5**。

这是供官方 OKWW/OK Script 安装版加载的声骸评分目录。将整个 `echo-score` 文件夹复制到：

`D:\ok-ww\data\apps\ok-ww\working\ok_import\echo-score`

重启 OKWW 后，在“截图方式”页面选择鸣潮窗口并开始捕获，再到“声骸评分”页面打开右上角总开关。

目前经过测试，可识别游戏的简体中文和繁体中文界面中的单个声骸主副词条及数值。其他游戏语言尚未测试。

本包不覆盖宿主程序源码，只注册一个设置任务和一个隐藏后台识别任务。

## 调谐概率与设置

在当前评分和理论最高分之外，可显示继续普通调谐后达到当前上限的估计概率、期望最终评分，以及最终评分**大于或等于**自定目标的估计概率。

- “显示调谐概率”：默认开启。
- “目标评分”：默认 `40.0`，必须为有限、非负数值，不设 50 分上限。
- 概率计算在后台执行，使用有界缓存；计算中和识别不满足模型要求时显示状态提示。
- 名称校验忽略开头的明确图标字符（`+＋✦✧★☆·•`），仍要求完整名称；未知名称不会通过概率校验。
- 0.4.5 改为“读取成功就锁定位置”：首次有效识别并定位到明确 COST 后，缓存逐行 OCR 区域及完整绘制坐标，包括 X、Y、宽高、档位和评分位置。缓存读取成功时不再做全屏定位或重算列边界，OCR 框在区域内的小幅变化不会改变绘制位置。
- 每次仍捕获新画面，在固定区域读取新的完整名称和数值，不缓存旧名称、数值、评分或概率。不同声骸位于相同位置时，可以直接显示新读取的有效词条。
- 固定侧栏检查区域覆盖所有可能的词条槽位及页面信息；检查行数、配对、候选名称、数值和单位，并与逐行读取结果核对。单个图标前缀只能作为候选，必须由当前逐行裁剪确认完整名称。
- 识别失败、行数变化或切页时废弃缓存，在同一截图上最多重新定位一次；分辨率变化、关闭功能、窗口隐藏或任务销毁也会清除缓存。重新读取失败时清除旧结果，显示识别状态。
- 初次名称裁剪仍使用多行长名称对齐证据，并由至少两种不同名称的同帧裁剪结果确认；不按前缀字符或字高猜图标宽度。缺少可靠文字起点时保留完整行范围，不强行裁掉首字。
- 后台配置检查间隔为 500ms。成功缓存帧最多九次 OCR（一次侧栏检查、七行读取及可选的独立 COST 小区域）；失败帧包含一次重新定位，合计最多十七次 OCR。实际刷新速度取决于宿主耗时，未承诺实机持续达到 2Hz。
- 只有完整名称、有效数值/单位和合法副词条档位可以进入位置缓存；未确认或冲突时不保留旧评分。稀有度、等级及完全未被 OCR 发现的整行仍无法证明，请核对“已识别 N/5”。
- 底部品牌横幅已停止绘制，并清除旧版本遗留的绘制项。
- 摘要固定左上锚点与最大宽度；较长诊断换行或截断，不因识别/计算状态改变而整体跳动。

“当前评分”沿用原有评分规则：主词条按 +25 满级值计分，再加已识别的副词条。预测保留模板权重、逐词条截断和 50 分基准；50 分是评分尺度，并非强制封顶。期望最终评分是概率加权平均，不保证能实际抽到该分数。

## 概率模型与数据来源

先阅读 [声骸调谐概率：中文说明](PROBABILITIES.zh-CN.md)，其中包含全部词条档位、概率表与计算公式。该说明依据韩文官方公示整理，并非官方中文原文。

来源：[Kuro 官方韩文概率公示](https://sdk-global.kurogames.com/pro/agreement/common/language_ko/product_info)，访问日期：**2026-10-02**。使用其中普通五星声骸调谐的词条类型与数值档位概率。

- 共 13 种副词条；每次从尚未出现的类型中等概率抽取，类型不重复。已识别出的类型从后续候选中排除。
- 暴击、暴击伤害使用暴击组的八档概率；其公示概率之和为 `99.9999%`。
- 攻击%、防御%、生命%、固定生命、共鸣效率和四种伤害加成使用普通组的八档概率；其公示概率之和为 `99.9998%`。
- 固定攻击与固定防御分别使用自己的四档概率；各自的公示概率之和为 `100%`，不能与普通组或彼此混用。
- 上述每个概率组单独按其公示总和归一化，消除公示四舍五入造成的微小质量缺口。完整档位和概率请以官方链接为准；代码中的值是本版本采用的快照。
- **假设**：不同次调谐的数值档位相互独立；该韩文公示对其他地区的普通五星声骸同样适用。公示本身不等于对这些假设的逐项验证。

模型枚举类型组合，并合并同一评分的概率质量，保留零权重词条和评分截断后产生的并列结果。达到当前上限的概率包含所有能达到该分数的组合，不只是某一种“最佳词条”组合；达标概率包含恰好等于目标的结果。五条副词条全部解锁时不再存在未来随机性，期望最终评分即当前评分，目标概率按当前评分是否达标给出。

计算是确定性的，没有随机抽样误差；但输入为官方已四舍五入的公示值，且存在模型适用性假设，故结果是**估计概率**，不是服务器内部概率的精度承诺。

## 必须核对的前提

所有概率和期望均以“**普通五星声骸，且已解锁词条被完整、准确地识别**”为条件。当前界面识别不能可靠证明声骸稀有度、等级或 OCR 完整性。即使已识别行全部合法，也可能仍有整行漏识别，不能据此把遗漏的词条当成未解锁槽位。

请核对主副词条、数值、单位、COST 和已解锁行数。模型会拒绝可发现的未知、重复、缺值、非有限、档位或单位异常等数据；拒绝异常并不意味着能发现所有 OCR 错误。声骸重构、锁定词条后的重洗及其他改变候选池的机制均不适用。

## 开发验证

在完整分发仓库根目录可运行：

```bash
python tools/package_echo_score.py
python -m unittest discover -s tests -v
python tools/benchmark_echo_probability.py
python -m compileall -q echo-score tools tests
```

打包器保留顶层 `echo-score/`，固定 ZIP 元数据并排除缓存；归档测试逐文件核对内容字节。每次修改此目录后应重新打包。概率模块和打包工具仅使用 Python 标准库，UI 仍使用 OKWW 已有依赖。

本次 0.4.5 开发环境未执行 Windows GUI、OKWW 宿主或实际游戏验证；也未执行无法访问的主项目重建、主项目测试或 Windows 安装目录同步。目标机器上的集成验证仍需单独完成。
