# OKWW 声骸实时评分

这是一个通过 OKWW（ok-script 机制）加载的《鸣潮》声骸实时评分功能。它复用 OKWW 的 OCR 图像识别能力，评分逻辑参考 [XutheringWavesUID（小维）](https://github.com/Loping151/XutheringWavesUID)。

> 当前版本为玩票性质的 BETA 版。请在了解相关风险后按需使用。项目不会修改 OKWW 宿主程序源码。

## 功能

在查看或调谐单个声骸时，工具会显示：

- 主词条及其分数贡献（红框区域）；
- 已解锁副词条及其分数贡献（白框区域）；
- 当前总分：按 +25 满级主词条计分，再加已识别的已解锁副词条；
- 理论最高分：剩余副词条均出现最有效词条、且数值达到最高档位时的分数；
- 达到当前上限的概率：继续普通调谐，最终评分达到当前理论最高分的估计概率；
- 期望最终评分：剩余副词条按概率分布调谐后的平均最终评分；
- 达到目标评分的概率：最终评分**大于或等于**自定目标的估计概率。

这些信息可以帮助你判断声骸是否值得继续开启副词条。

## 游戏语言

目前经过测试，支持游戏设置为**简体中文**或**繁体中文**时识别单个声骸的主词条、副词条及数值，并进行评分。繁体中文词条和“角色名裝配中”会在匹配前转换为评分模板使用的简体名称。其他游戏语言尚未测试。

当前脚本版本为 **0.4.11**，按可配置间隔（默认 1000ms）读取当前完整画面，实时更新词条框、评分、概率与档数；已移除 OCR 位置缓存、图标裁剪及多行共识定位。保留独立档数列、无底部横幅及 XW-UID 的「心-通用」和「锁暝-通用」评分模板。更新后请重启 OKWW，使新的脚本和模板列表加载生效。

## 调谐概率的适用范围

概率结果以“**普通五星声骸，且当前已解锁副词条全部被正确识别**”为前提。界面识别不能可靠确认稀有度、等级或是否漏识别了整行词条，因此看到结果不代表这些前提已被验证。使用前请核对识别结果；声骸重构、锁定词条后重洗等机制不在模型范围内。

中文公式、13 种词条档位及概率表见 [声骸调谐概率：中文说明](echo-score/PROBABILITIES.zh-CN.md)（依据韩文官方公示整理，并非官方中文原文）。

模型采用 [Kuro 官方韩文概率公示](https://sdk-global.kurogames.com/pro/agreement/common/language_ko/product_info)（访问日期：2026-10-02）的普通调谐数据：13 种副词条等概率、不重复抽取；数值档位按各类公示概率计算。公示的四舍五入数值会分别归一化；不同次调谐的数值档位相互独立，以及该韩文公示适用于其他地区，均是模型假设。计算对该模型是确定性的，但公示精度和适用性有限，显示的是估计概率，不是服务器精度或结果保证。详细分组、计分方式和限制见 [`echo-score/README.md`](echo-score/README.md#概率模型与数据来源)。

## 安装

### 1. 安装 OKWW

本功能依赖 OKWW 的 OKScript 机制和 OCR 能力。请先从 [ok-wuthering-waves](https://github.com/ok-oldking/ok-wuthering-waves) 了解并安装 OKWW；使用前请阅读其说明并自行评估风险。

### 2. 安装声骸评分脚本

本仓库提供可直接复制的 [`echo-score/`](echo-score/) 目录和同内容的 [`echo-score.zip`](echo-score.zip)。安装步骤：

1. 解压 `echo-score.zip`，或直接使用仓库中的 `echo-score` 文件夹；
2. 将整个文件夹复制到 OKWW 安装目录下的：

   ```text
   data/apps/ok-ww/working/ok_import/echo-score
   ```

   例如：

   ```text
   D:\ok-ww\data\apps\ok-ww\working\ok_import\echo-score
   ```

3. 重启 OKWW；
4. 在 OKWW 的“截图方式”页面选择鸣潮窗口并开始捕获，然后到“声骸评分”页面使用右上角的开/关按钮启用功能。评分设置修改后即时生效，无需点击任务“开始”。

### 3. 选择评分模板

打开“自动匹配评分模板”后，工具会根据单个声骸查看界面的“角色名装配中”选择模板，并在调谐界面沿用上一次识别结果；也可以在可输入搜索的下拉框中手动选择模板。

### 4. 配置调谐概率

- “读取间隔（毫秒）”：默认 `1000`。在现有“声骸评分设置”中修改，保存后自动应用，无需重启；缩短间隔会唤醒现有调度检查，不必等待旧长间隔结束。
- 间隔须为正整数，范围 `1–2147483647` 毫秒，上限来自宿主原生整数控件。间隔越小，OCR 负载越高；实际刷新速度仍受识别耗时限制。旧配置缺少此项或保存值无效时按 `1000` 毫秒运行。
- “显示调谐概率”：默认开启，可随时关闭概率展示；
- “目标评分”：默认 `40.0`，接受有限、非负的数值，不设 50 分上限；达标包含恰好等于目标；
- 修改模板或目标后会重新计算。首次计算在后台进行；等待时保留“概率计算中…”，概率无法计算时统一显示“概率算不出来”，不展示内部识别或计算原因。校验与计算规则不变。

0.4.11 使用简单实时流程：读取间隔默认 **1000ms**，可在设置页修改，每次启用且有有效截图时只进行一次完整画面 OCR，并直接解析这次结果。无位置缓存、图标裁剪补读、多行共识对齐或额外侧栏复核。词条框随当前原始坐标更新，不锁定旧位置；空画面、切离声骸页面或读取异常时不保留旧分数和档数。

档数仍显示在独立列，每次按当前词条和数值计算，分数显示在右侧。评分与概率直接共用同一组规范化词条名称和数值，不再额外要求原始 OCR 名称完全匹配。名称处理仍使用原有繁简转换、空白规范化和词条匹配，不新增图标裁剪或前缀删除。评分可解析为已知类型的名称，概率使用同一类型；仍无法映射的未知类型不能用于概率计算。原有匹配也可能将误识别映射为另一合法类型，使用前仍需核对。

评分、COST 读取及自动/手动模板选择沿用单次原始识别流程。评分与概率使用同一组当前已配对词条，未被采用的未配对 OCR 碎片不再额外阻止计算。概率保留数值有限性、单位、合法档位、槽位数、重复类型及主词条/COST 兼容校验；已知零权重副词条仍占用已开启槽位。结果是基于已识别词条的条件估计；“已识别 N/5”不是已解锁行数的证明。若真实词条缺少名称或数值而未被配对，估计可能不适用于这件声骸；未识别到的整行、稀有度和等级仍无法证明。概率模型的纯输入结果复用与后台计算保留，不复用旧画面的 OCR 内容。实际刷新速度取决于宿主耗时，设置的间隔不是实机性能保证。

底部品牌横幅不再绘制，启动、刷新和关闭时也会清理旧版本残留。摘要保持固定左上位置与最大宽度，过长提示换行或截断。实际 Windows 游戏 OCR 的速度与识别效果仍需在目标设备上验证。

所有最终评分预测沿用当前模板与 +25 主词条计分，不会把声骸当前等级误作新的评分标准。概率只描述继续调谐的随机结果，不代表培养收益或提升建议。

## 构建与目录结构

源码位于 [`echo-score/`](echo-score/)，其中包含设置页面、后台识别任务、繁简文字规范化、评分逻辑和角色模板数据。`echo_probability.py` 是不依赖 GUI 的概率模型；`echo_probability_service.py` 负责有界缓存与异步计算，避免首次计算阻塞识别刷新。没有新增第三方运行依赖。

`echo-score.zip` 是源码目录的打包副本，包含顶层 `echo-score/` 文件夹。确定性打包工具固定文件顺序、时间戳和权限，使用 ZIP 的存储模式避免压缩库版本影响；排除 Python 字节码、缓存目录和 `.DS_Store`，不包含测试或开发工具。

在仓库根目录运行以下开发检查；源码修改后需先重新打包，否则归档一致性测试会失败：

```bash
python tools/package_echo_score.py
python -m unittest discover -s tests -v
python tools/benchmark_echo_probability.py
python -m compileall -q echo-score tools tests
```

测试会逐文件核对 ZIP 与 `echo-score/` 的内容字节，并检查打包结果可重复。基准脚本用于检查剩余 0–5 个词条槽位时的计算耗时；应在目标设备上另行测量。

本次 0.4.11 开发环境未执行 Windows GUI、OKWW 宿主加载或实际游戏画面的验证，也未执行无法访问的 `E:/ok-wuthering-waves` 主项目重建、主项目测试和 `D:/ok-ww/...` 安装目录同步。这些环境相关检查仍需在对应 Windows 机器上完成；本仓库的标准库测试不能代替它们。
